SMARTER.POKER SIGNED SOLVER WORKER DEPLOYMENT
=============================================

The former God Mode direct-ingest path is permanently retired.
`scripts/ingest_god_mode.py` is a fail-closed tombstone and must not be copied,
wrapped, scheduled, or restored. M1 and M2 must never hold any Supabase URL,
anon credential, service credential, or database connection string. Remove all
legacy values from machine/user environment settings, `.env` files, scheduled
tasks, wrappers, and shell profiles. Rotate any historically exposed database
credential centrally before either worker is enabled.

The only supported publisher is:

    scripts\preflop-deep\run_machine.py

It sends bounded HMAC-authenticated requests to exactly:

    https://smarter.poker/api/training/solver-worker

Operator-controlled prerequisites
---------------------------------

1. Deploy the protected signed-worker API and migrations first.
2. Keep the solver provenance allowlist empty until the binary, protected
   pipeline commit, manifest, target ledger, and pre-existing UUIDs have been
   independently verified under the admission runbook.
3. Provision two different 32-byte HMAC secrets in the authorized secret store:
   one for M1 and one for M2. Give each host only its own secret. Never copy one
   host's value to the other and never store either value in this repository.
4. Install the approved PioSOLVER console executable and independently record
   its SHA-256. Install the approved range directory and checksums.
5. Disable every legacy task or wrapper before the supervised canary.

Required per-process environment names
--------------------------------------

    SOLVER_WORKER_API_URL
    SOLVER_WORKER_HMAC_SECRET
    PIO_EXE
    PIO_SOLVER_VERSION
    APPROVED_PIO_BINARY_CHECKSUM
    PIPELINE_COMMIT
    APPROVED_MANIFEST_CHECKSUM
    RANGE_DIRECTORY

The HMAC value must come from the authorized per-host secret store. Do not echo
it, pass it on a command line, put it in a batch file, or persist it with SETX.
The launcher validates the exact endpoint, manifest, protected pipeline bundle,
range files, and Pio executable before starting solver work.

Safe validation and launch
--------------------------

From the protected repository checkout, run the non-mutating environment check:

    scripts\windows-setup.bat M1

or:

    scripts\windows-setup.bat M2

The check never connects to Supabase and never starts the solver. After the
operator gate is complete, start exactly one supervised canary:

    python scripts\preflop-deep\run_machine.py M1 2 0

For M2, only after M1's signed heartbeat and one-artifact admission are verified:

    python scripts\preflop-deep\run_machine.py M2 2 1

Do not enable either worker while the canonical manifest release gate is closed,
while the target ledger has a missing or duplicate UUID, or before the external
credential-rotation and provenance-approval steps are complete.

# Web Push (VAPID) -- PepNationLab parity clone

Date: 2026-08-19
Tier: 3 (architecture: new schema, new API surface, provider swap)
Migration: `supabase/migrations/20260819120000_webpush_vapid_stack.sql` (APPLIED to production)

## Why

Push notifications on smarter.poker did not reach phones. Root causes found:

1. **`pages/_app.js` destroyed every push subscription on every deploy.**
   The cache-buster unregistered ALL service workers whenever `BUILD_VERSION`
   changed. Unregistering a service worker destroys its `PushSubscription`.
   `BUILD_VERSION` changes on every deploy, so every deploy silently wiped
   every subscription while OneSignal kept reporting successful sends against
   endpoints that no longer existed. This is the single biggest cause.

2. **Two service workers competed for the origin.** OneSignal registered
   `/OneSignalSDKWorker.js` alongside next-pwa's `/sw.js`.

3. **No delivery truth anywhere.** FCM and Apple return 2xx for endpoints whose
   device is long gone. Nothing distinguished "accepted" from "displayed", so
   every dashboard read green while phones stayed silent.

## What changed

OneSignal is retired. Delivery is now self-hosted VAPID Web Push (RFC 8030).

### Database (applied, verified)
- `push_subscriptions` -- one row per device endpoint, with `last_used_at`
  (what we sent) and `last_receipt_at` (what the device confirmed displaying).
- `push_outbox` -- durable queue and audit trail; every send decision is
  recorded, including suppressions and why.
- `push_dispatch_runs` -- unique `(job, slot)` so a double-fired dispatcher
  cannot double-send; also the liveness signal push-health reads.
- `notification_preferences` += `mute_all`, `browser_push`, `push_type_prefs`.
- `notifications` += `read_at`, backfilled (626 rows), with
  `trg_sync_notification_read_state` keeping `read` / `is_read` / `read_at`
  consistent no matter which one a writer touches. This is what let the new
  code land without editing any existing reader in Club Arena, Commander or
  the social feed.
- RPCs `claim_push_outbox_batch` (FOR UPDATE SKIP LOCKED),
  `requeue_stuck_push_outbox`, `prune_old_notifications`.
- `is_admin()` created -- it did not exist. Staff = `profiles.role IN ('admin','god')`.

### Decisions worth remembering

- **`public/sw.js` is generated by next-pwa and gitignored.** All custom service
  worker logic must live in `worker/index.js`, which next-pwa compiles to
  `public/worker-<hash>.js` and `importScripts()` from `sw.js`. Do not try to
  hand-write `public/sw.js`.
- **next-pwa runs with `disable: !process.env.VERCEL`.** There is no service
  worker on localhost, so push can only be tested on a Vercel deployment.
- **`/api/push/rotate` is deliberately unauthenticated.** A service worker
  cannot read the Bearer JWT out of localStorage, but `pushsubscriptionchange`
  fires when no user is present. The old endpoint is the proof of device
  identity; the route only ever migrates an existing row and never creates one.
- **Crons go to Open Claw, not `vercel.json`** (CLAUDE.md section 11).
  `pages/api/cron/` grew 24 -> 26, well under the CI cap of 45.
- **`react-onesignal` stays in `package.json`.** Nothing imports it any more,
  but removing it desyncs `package-lock.json`, and `npm ci` fails hard on a
  mismatch. Drop it in a follow-up PR where the lockfile can be regenerated.
- **Files could not be deleted** (the migration ran from a create-only mount).
  `src/lib/onesignal-server.js`, `src/lib/commander/pushNotifications.js` and
  `src/contexts/OneSignalContext.jsx` are now VAPID-backed shims that keep the
  old names and signatures. `public/OneSignalSDKWorker.js` is a tombstone that
  makes already-installed OneSignal workers unregister themselves -- that one
  must keep being served until the old worker population ages out.

## Verified

- Outbox durability, against production: claim, attempt increment,
  double-claim protection, stuck-requeue, max-attempts ceiling. All asserted.
- Read-state trigger: all three representations stay consistent across insert
  and all three update paths. 10,782 existing rows: zero drift.
- Import resolution across all 32 touched files: clean.
- Parse check across all JS/JSX: clean.
- 8 Immutable Rules: no `.single()`, no raw `@supabase/supabase-js` in API
  routes, no `.limit()` on arrays, no emoji, no conflict markers.

## NOT done -- required before this works

1. **Set the four VAPID env vars in Vercel** (`hub-vanguard`, all environments).
   Values are in `.env.vapid.generated` (gitignored). `VAPID_PUBLIC_KEY` and
   `NEXT_PUBLIC_VAPID_PUBLIC_KEY` must be byte-identical. These keys can NEVER
   be rotated once users subscribe.
2. **Deploy.** Until then `isPushConfigured()` is false: outbox rows queue
   rather than send, and drain automatically once the keys land.
3. **Run `bash scripts/deploy-openclaw.sh`** so the Hetzner dispatcher picks up
   the two new jobs. The repo file and the live dispatcher must not drift.

## Saved cash-game simulation and provenance

The simulator had recorded 444 consecutive `no_rows_generated` cycles. Its
model accepted 2,599 PokerAtlas cash-game catalog patterns across 479 venues,
but all catalog table counts were intentionally null. The old normalization
converted those values to zero, then treated the empty output as a valid model.

The repaired model:

1. Preserves real Bravo history as the highest-priority source when it exists.
2. Uses the saved PokerAtlas cash-game catalog as a conservative one-table
   baseline only when observed counts are absent.
3. Applies the existing day and hour model, allowing an estimate to resolve to
   zero, one, or two tables.
4. Resolves venue names from the durable venue directory when the transient
   live table is empty.
5. Refuses to publish when fewer than 50 venues are generatable.
6. Keeps every generated row explicitly simulated and never describes a model
   value as a live observation.

A fresh model probe produced 2,599 game rows across 479 venues. At the sampled
overnight hour, 22 venues had modeled activity totaling 102 tables. All 2,599
rows retained simulated provenance and every venue name resolved without a slug
echo.

One shared adapter now joins cash games by Bravo slug, PokerAtlas slug, canonical
slug, and normalized venue name. The lobby, discovery application, state and
city cards, venue cards, comparison table, map popups, and venue profiles use
the same provenance contract:

- observed: `Live Now`;
- modeled: `Approx.` or `Estimated`; and
- mixed: `Live + Estimated`.

Zero-table catalog signals remain visible as estimates instead of disappearing,
and no game-object array can stringify to `[object Object]` in a map popup.

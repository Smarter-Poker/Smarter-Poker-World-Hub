# External access checkpoint template

The legacy USER-SETUP filename and frontmatter key remain compatible. They do not impose human approval or assume dashboard, account or credential work is human-only. Read root AGENTS.md and the operating law first.

Record only a demonstrated missing input or explicit tool-required handoff after checking configured supported access. Assigned configuration and credential repairs need no additional owner approval. Preserve the canonical identity, intended permissions and secret store. Never print secret values, read environment-file values or substitute an unrelated credential.

For each unresolved item record:

- The assigned action and affected service.
- The exact missing capability and evidence; name any tool policy requiring handoff.
- The concrete prepared action and minimal missing input, such as a saved key-file path, never its contents in chat.
- The existing operation identity and actual pending/unknown state.
- The independent work completed while the input is pending.
- The command or behavior that will verify the real result.

Keep dependent work pending until access is available. Continue all independent checks and eligible publication personally. Mark the item complete only after verifying the affected authentication/configuration result; a supplied input or successful click alone is insufficient. Do not generate new accounts, infrastructure, scheduled agents or fallback publishers as a workaround.

# Checkpoints record verified progress

Use root AGENTS.md, docs/agent-policy/OPERATING-LAW.md and PUBLISHING.md.
No additional human approval is required for authorized work. A checkpoint is
an evidence record, not a human gate, release label or reason to pause delivery.

## Verification

Run the actual applicable checks and inspect the affected behavior with the
available authorized browser, CLI, API or native tools. Include visual, mobile,
realtime and persistence checks when relevant. Record exact source, commands,
results, provider identity and remaining limitations. Repair failures and verify
the final candidate before continuing. Never auto-approve unexecuted checks.

Legacy checkpoint:human-verify and human_needed records mean verification is
still outstanding. The assigned agent performs that work directly; an invented
approval response does not satisfy it. Keep source, tests, merge, installation,
publication and live verification separate.

## Decisions and unavailable access

Resolve ordinary implementation decisions using the existing assignment,
requirements and evidence. Ask only for materially missing requirements or an
unavailable input; continue independent work while the answer is pending.
First inspect configured tools and authorized credential metadata. Necessary
credential repairs follow current owner authority. Never request secret contents
in chat, scrape environment files or substitute a different service identity.

If a tool explicitly requires user handoff or authentication cannot be completed,
name the exact constraint and source, prepare the concrete action and finish all
independent work. That limitation is not a renewed owner-approval requirement.
Preserve any pending operation identity and verify its result before retrying.

## Continuity

Keep the existing checkpoint with the owned checkout, branch, PR, tested inputs,
pending runs, installed/live identities, blocker evidence and next action.
Recover existing source and ownership before replacing an unavailable helper.
Do not wait for another chat to do work the assigned agent can complete.
No checkpoint authorizes new delegation, another product phase, a watcher,
a recurring agent, a release timer or a parallel publisher.

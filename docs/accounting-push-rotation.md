# Authenticated rotation successor — source only / UNRUN

This source depends on CA component `20260914164500_push_rotation_preserves_current_subscription_ownership.sql` after the existing 164000 enrollment component. No migration, test, build, provider send or release was executed. Only the protected local pipeline may qualify the candidate.

`/api/push/rotate` now requires a verified request account before looking up any subscription. Endpoint/key possession alone cannot authorize it. Both old keys, active actor-owned source, recorded non-null device identity and exact decimal row revision enter one service-only CAS transaction using the enrollment lock. An existing target endpoint or another active same-device row is refused, never reassigned. Retirement and replacement succeed together; there is no compensating reactivation or independent table-write fallback. Preferences remain unchanged.

All updates advance a row-local bigint revision. The adapter requests PostgREST `rotation_revision::text` and rejects numeric/malformed revisions, preserving values beyond JavaScript safe integers. Native SQL and the adapter projection both need actual protected qualification. Missing function/column, source conflict, failed transaction and malformed receipt cannot claim success. After a lost committed response, retry refuses the now-inactive source without another mutation; a later authenticated enrollment remains recovery.

**Compatibility boundary:** the existing workers cannot present a localStorage bearer. Their sessionless rotation requests now receive 401 with zero writes and are logged as unconfirmed. They can create a local browser subscription, but cannot certify server enrollment. Foreground authenticated enrollment/replacement is still available; its sync throttle/account-switch behavior remains separately unresolved. Automatic background rotation requires a client-held account/epoch capability and is not restored by this patch. No full automation claim is made.

A verified request account is not a revocable installation generation. A delayed request that obtains another account's current valid authentication, revocation after API authentication, same-origin account transitions, stale provider mutation, already-accepted WebPush/FCM messages and authenticated per-device display acknowledgment remain unqualified. This patch leaves generic accounting banners, social content, provider retry budgets, endpoint receipt telemetry, money and invoice delivery semantics unchanged.

`__tests__/push-rotation-ownership.test.mjs` exercises the real route factory/adapter and actual worker sources with controlled auth/database/network boundaries. It covers anonymous-before-read refusal, actor scoping, precision, CAS conflict/no fallback, missing proof/device, malformed receipts and worker refusal handling. It does not prove real JWT verification, installed PostgREST casting, native SQL concurrency, browser lifecycle or physical device delivery. The existing device/zombie test files were updated only where they previously required unsafe independent retirement/compensation; their other behavior remains. CA's isolated regression and concurrency spec are required separately. All revised/new tests are UNRUN.

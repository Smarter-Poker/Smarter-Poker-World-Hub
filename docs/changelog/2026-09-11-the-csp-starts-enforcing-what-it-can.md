# The CSP Starts Enforcing What It Can

Before: next.config.js has shipped `Content-Security-Policy-Report-Only` for the whole smarter.poker origin since Phase 6.1.14, above a comment saying it graduates to `Content-Security-Policy` "once violations have been monitored and confirmed zero". No monitoring existed. The policy carries no `report-uri` and no `report-to`, so a violation writes one line to one browser console and is forgotten. The same file records what that costs: Sentry's ingest host was missing from `connect-src` for ten days, and the comment written when it was fixed says the only symptom was "a line in the console that nobody reads". The enforced header existed but carried one directive, `upgrade-insecure-requests`, and only under `process.env.VERCEL`.

Evidence first: Club Arena's `tests/e2e/production-csp-violations.spec.ts` now collects `securitypolicyviolation` events from deployed production — they fire for a report-only policy too, with `disposition: "report"` — across five arena routes and three Hub routes, on every post-deploy run. Signed in against production on 2026-09-11 it reported zero violations. That is the first time the question this comment has been asking was answered with data.

Even so, this does not flip the whole policy, and eight routes are not the whole Hub. The directives that say WHERE A RESOURCE MAY COME FROM — `script-src`, `style-src`, `connect-src`, `img-src`, `font-src`, `media-src`, `frame-src`, `worker-src` — break a page the moment one is incomplete, and the Sentry incident is the proof. They stay report-only.

What graduates is the other kind: the four directives that govern INJECTION rather than loading. None of them names a resource this site fetches, so none can break a page by being slightly incomplete. Each was checked against the source before it moved:

- `object-src 'none'` — no `<object>` or `<embed>` exists in src, pages, public or app. (The three `Promise<object>` hits are JSDoc; the guard's regex excludes a `<` preceded by a letter for exactly that reason.)
- `base-uri 'self'` — no `<base>` tag exists either, except the one `pages/api/proxy.js` injects into proxied publisher HTML so relative URLs resolve against the original domain. That endpoint sets its OWN enforced `Content-Security-Policy`, including `base-uri https:`, and an API handler's `res.setHeader` REPLACES the header from `headers()` rather than adding to it. Measured live on 2026-09-11: `/api/proxy` returns the proxy's policy and not the global one, so the injected base tag is unaffected. That replacement is now pinned by a test, because the day it stops being true is the day the reader breaks.
- `form-action 'self'` — no form anywhere posts off-origin, and the proxy rewrites every proxied form action back through `/api/proxy?url=…`, which is same-origin.
- `frame-ancestors 'self'` — already enforced three headers up as `X-Frame-Options: SAMEORIGIN`. This is the modern spelling of a restriction the site has always had, so it changes nothing at all.

The enforced header is also no longer Vercel-only. It used to be wrapped in `...(process.env.VERCEL ? [...] : [])`, which left localhost and any non-Vercel deployment with no enforced policy whatsoever. Only `upgrade-insecure-requests` is still conditional, now inside the directive list, for the documented reason: `next start` serves HTTP locally and WebKit correctly upgrades every same-origin chunk, leaving the page blank and making a real Safari CI pass impossible. The other four are scheme-independent, so localhost is protected by them too.

Verification: `node --check next.config.js` passes, and `__tests__/the-injection-directives-stay-enforced.law.test.mjs` is seven assertions in 3.8s, wired into build-safety-gate CHECK 5. It pins that the four are enforced, that none of the resource-loading directives has joined them, that the enforced header is unconditional, that the proxy still sets its own policy with a permissive `base-uri` and still injects the `<base>` tag, that no `<object>`/`<embed>` or off-origin form has appeared, and that `X-Frame-Options` is still there — legacy browsers and embedded webviews honour only XFO, and this platform is opened inside a native app webview.

One note on writing that guard: its first version reported four `.mp3` files under public/audio as forms posting off-origin. Compressed audio contains every byte sequence eventually, `action="http` included. It now greps source extensions only and skips binaries, which also took it from nineteen seconds to under four.

# Dense ICM setup keeps the same commands with a linear ordering guard

The final setup guard searched the entire command list for every ICM point, even when a session could reuse the exact table. Dense approved models therefore spent quadratic CPU time validating command order before communicating with Pio.

Build a first-occurrence position index once, then check the same build/model/go inequalities. `setdefault` preserves the former `list.index` semantics for repeated command strings. All model validation, commands, ordering refusals, session identity and quality gates stay unchanged.

The existing pipeline suite retains a comparison-count regression and duplicate-boundary cases. Pure approved-input qualification compares the complete old and new command bytes for the densest model and measures the guard separately. Existing licensed five-case exact-session proof remains applicable because the command bytes are unchanged; no new licensed solve is required for this guard-only change.

The ongoing frozen R7 information study continues with its original producer revision. This source repair is for subsequent approved work; it does not change that study or certify any dataset.

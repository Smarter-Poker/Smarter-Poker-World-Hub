# Empty series cycles and unavailable graphics remain usable

The series runtime incident d1a6ebe0 came from its eight-hour no-write watchdog. The November15 01:22 log shows a successful zero-error cycle wrote no new events, slept on its normal six-hour schedule, then was killed solely because no rows changed. A restart cannot create new source events. The daemon now preserves its business schedule after empty successful cycles; real programming errors still exit unsuccessfully and existing degraded-cycle backoff remains unchanged. A virtual-clock regression runs three empty cycles over twelve hours without a restart and another verifies a programming failure still fails.

The two actual November14 app crashes3197/3198 were WebGL context creation failures. The hub now checks graphics capability before mounting Three.js and uses the same visible card list, approved images and real navigation handler in ordinary HTML when graphics is unavailable. Render errors on capable devices still reach the existing boundary and durable crash report. The HTML card navigation also replaces the boundary's nonfunctional offline label. GPU capability, probe disposal, card visibility and click wiring are regression tested in the existing required gate. Auth diagnostics remain unchanged: daily crash metrics already exclude them.

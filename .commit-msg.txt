feat(ads): placement verbs, image creatives, and an experiment key

POST created the advert plus exactly ONE placement and PATCH never touched
ad_placement at all, so the panel could make a campaign live on one surface and
then never move it: no second surface, no cap change, no pausing one surface
while another kept running. Every multi-slot placement in production had been
written by an agent, in a migration - and the per-placement reporting shipped
earlier the same day described a dimension the editor could not manage.

?kind=placement on POST, PATCH and DELETE, beside the catalog verbs rather than
in a second file: the authorization, the rate limit and the service-role client
are the same, and a second route would be a second place for them to drift.

Every branch says what happened rather than 500ing. A duplicate returns
'already has a placement on that slot' - reachable from a browser for the first
time today, and only meaningful because the unique key was fixed in club-arena
migration 20260828110000, where it turned out NULLS DISTINCT meant it had never
fired on a real row. A club that does not exist returns so, now that club_id is
a real foreign key. A placement deleted in another tab returns 'no longer
exists', because the update asks which row it touched rather than trusting
PostgREST's { error: null } on a zero-row match. Removing the LAST placement
reports orphaned:true, because an advert with no placement looks perfectly
healthy in a list and runs nowhere.

IMAGES. cleanImageUrl refuses anything that is not a same-origin path, matching
the CHECK the database now carries; hubAds maps image_url and the rail renders
it with a glyph fallback when the file is missing. The fetch happens on render
without the viewer doing anything, so an external host would hand every
player's IP and user agent to a third party chosen by whoever typed the URL.
Three locks - database, API, render - because that last one is the one that
actually protects the player if the others are loosened.

EXPERIMENTS. experiment_key rides through create and update. Two campaigns
sharing one are variants of a single test; the weighted draw has split traffic
between them correctly since it landed, but nothing recorded that they were
related, so nobody could read the result.

The weight clamp floor moves from 0 to 1 to match ad_catalog_weight_positive:
the panel says 1 rather than the save failing on a constraint the operator
cannot see.

22 source-pinned tests pass; the route, the rail and the client all parse under
Babel with sourceType module + jsx.
